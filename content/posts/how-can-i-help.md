After years of working in open source, the most common question I get asked looks something like this:

*"Hi, this is a cool project! I'd love to contribute, but I didn't see any good first issues. How can I help?"*

This message is spam. As someone that encourages anyone to get involved in open source, this is not the way to do it.

The problems with this message start with the fact that it is essentially a cold call. This message usually comes from a brand new face, bright eyed and bushy tailed seemingly ready to embark on a long open source journey. They just need a little nudge in the right direction. There's nothing wrong with asking for a starting point, right?

The problem is this is almost always my first and last interaction with someone. It's extremely rare for this question to be followed by any meaningful effort to actively contribute (if any contribution at all). The reason for this lies in the nature of the question itself.

Reaching out to maintainers is an applaudable effort in and of itself, and maintainers should be open to any correspondence. That's the nature of maintaining an open source project. However, there are several major red flags in this specific type of question.

The first is in its total ambiguity. Most often this question doesn't include any context about the person asking it or *why* they are asking to help out.

Maintainers don't save "easy issues" for a rainy day. If I come across something that's trivial to fix, I'll just fix it (unless I'm feeling particularly lazy). Would it be good for a project to constantly neglect so-called low hanging fruit, leaving open problems in their product?

All of this in mind, these are my answers to this question:

1. Thank you for your interest.
2. I do not have any good beginner issues, sorry.
3. Please feel free to join in any open conversation, meeting, or issue that you find interesting.
4. Please open any issue or pull request that you would like to contribute.

So, if you find an open source project you'd like to be part of, here is how I would recommend engaging:

1. Understand the project
2. Ask about specific work.
3. Have a motivation

"How can I help?" is a question that you ask *yourself*, not others. If you can't answer it, you're probably not ready to help (yet).

I know that all of these sounds like I'm turning away new contributors. I'm not. Believe me, I want as much help as I can get, and the point of this post is to help new contributors engage more effectively so they can be successful maintainers.
